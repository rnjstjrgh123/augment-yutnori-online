# 증강 윷놀이 온라인 — 증강 선택 흐름 수정판

Node.js 18+ / Express / Socket.IO 기반 멀티플레이 윷놀이입니다.

## 실행
1. 이 ZIP을 풀어 `package.json`, `server.js`, `public/`, `tests/`가 같은 폴더에 있는지 확인합니다.
2. 해당 폴더에서 `npm install`을 실행합니다.
3. `npm test`로 서버 흐름 회귀 테스트를 실행합니다.
4. `npm start`로 실행한 뒤 브라우저에서 `http://localhost:3000`에 접속합니다.

## 증강 선택 흐름
1. 대기실에서 모든 플레이어가 준비한 후 방장이 `게임 시작`을 누릅니다.
2. 서버는 게임 단계를 `augment`로 설정합니다.
3. 클라이언트는 증강 선택 모달을 열고 윷놀이판과 플레이 화면을 숨깁니다.
4. 각 플레이어가 증강을 확정합니다. 첫 플레이어가 선택해도 게임은 시작되지 않습니다.
5. 모든 플레이어가 선택한 뒤에만 서버 단계가 `playing`으로 바뀌고 클라이언트가 모달을 닫아 윷놀이판을 표시합니다.

## 수정 및 테스트
- 증강 선택 모달을 여는 함수가 게임 화면을 먼저 활성화하고 말판 영역을 숨기도록 정리했습니다.
- 모달 종료 시 말판 영역의 `hidden` 상태도 명시적으로 해제합니다.
- 시작 버튼 핸들러에서 서버가 보낸 실제 단계 값을 임의로 덮어쓰지 않도록 변경했습니다.
- 빽도 결과로 판 위에 말이 없는 경우 턴을 넘기는 코드에서 `nextTurn(r)`에 방 상태 인자를 전달하도록 수정했습니다.
- `npm test`는 두 플레이어의 방 생성/참가/준비/게임 시작/증강 선택/플레이 단계 전환을 모의 Socket.IO 환경에서 검증하고, 클라이언트 인라인 JavaScript 문법 및 핵심 UI 조건을 검사합니다.

## Render 배포 시 주의
저장소 루트에 `package.json`, `server.js`, `public/index.html`이 있어야 합니다. ZIP 안의 상위 폴더를 통째로 올리는 대신 이 파일과 폴더를 저장소 루트에 덮어쓰고 커밋한 다음 Render에서 해당 커밋을 배포하세요.

참고: 테스트는 로컬 모의 Socket.IO 환경에서 실행됩니다. 실제 Render 서비스의 브라우저/멀티플레이 환경에서 배포 확인까지 완료한 것은 아닙니다.
